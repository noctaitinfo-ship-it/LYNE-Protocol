# Conformance

Test your own implementation against the specifications without any LYNE code: the vectors are data, the runner
needs only a Python standard library, and your implementation talks to it through a small line-based protocol.

## LP 0.2 candidate-4 — the driver protocol

1. **Write a driver.** A driver is a process of your implementation that reads one JSON object per line on stdin
   (a vector: `id`, `context`, `steps`) and writes one JSON object per line on stdout with the outcome of each step.
   It may be in any language. The contract is
   [`lp-0.2-candidate-4/conformance/DRIVER.md`](lp-0.2-candidate-4/conformance/DRIVER.md): a fresh instance per vector,
   `context.now` as the clock, `context.candidate` as the candidate profile, and `UNSUPPORTED` for an operation you do
   not implement. `UNSUPPORTED` never counts as a pass.
2. **Run the vectors**, for example with a driver started as `./my-driver`:

   ```
   python lp-0.2-candidate-4/conformance/run_candidate4.py --driver "./my-driver" --name MINE
   python lp-0.2-candidate-4/conformance/run_candidate4.py --driver "./my-driver" --name MINE --modules common,lp02.federation,lp02.admission
   ```

   The runner feeds all four vector sets (candidate-1's core set, `lp02.channel` /2, `lp02.liveline` /1 and the
   version negotiation) under the candidate-4 profile. `--modules` limits the core set to the modules your profile
   implements; the profiles are in [`lp-0.2-candidate-4/MINIMAL.md`](lp-0.2-candidate-4/MINIMAL.md). The runner compares outcome, refusal code and
   the full result of each step, and prints `CANDIDATE-4 CONFORMANCE: PASS` or the failing steps.
3. **Or through the package check:** `python tests/verify_package.py --driver "./my-driver" [--modules …]`.

The package's candidate check (`python tests/check_candidate.py`) proves the candidate's tree is exactly the frozen
candidate (its MANIFEST and candidate hash).

**The Live Line data-channel profile** (`lp02.liveline` /1) is also proven between two independently written browser
peers in real Chrome; that proof is part of the evidence (`evidence/README.md`), not of the vectors.

## LP 0.1

LP 0.1's own tests are part of the immutable baseline (`lp-0.1/tests/`).

```
python -m pip install -r tests/requirements.txt
python tests/lp01_protocol_checks.py
```

This runs every protocol check of the locked test file:

- the schemas;
- valid, invalid, semantically invalid and tampered examples;
- signatures, JCS and the AES-GCM signaling;
- reproducible examples;
- the protocol text, threat model and changelog.

It does not run the three checks of the development repository the file was written in.

## One command for everything

```
python tests/verify_package.py
```

It checks:

- the checksums;
- LP 0.1 identity, and LP 0.1's protocol checks;
- the candidate (byte-identical to the frozen candidate-4);
- the schemas and the coverage;
- the secret scan;
- the manifest;
- that the status statements are truthful;
- the links.

It prints `LYNE-PROTOCOL PACKAGE: PASS` or `FAIL`.
